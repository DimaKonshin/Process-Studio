# Process Studio

## Архитектура

- Корневые маршруты находятся в `src/app/app-routing.module.ts`. Функциональные разделы загружаются лениво из `src/app/lazy-modules`. Раздел владеет своим routing module, layout и страницами.
- Страницы приложения собирают интерфейс из компонентов. Редактор и его модель живут в библиотеке `projects/workflow-designer`. Приложение импортирует библиотеку через `public-api.ts`.
- В `domain` описываем шаги, порты, связи и правила процесса на TypeScript. Эти модели независимы от Angular, Foblex и браузерных API.
- В `data-access` храним состояние редактора, читаем и записываем данные, проверяем формат на входе. В `presentation` отображаем состояние и переводим жесты Foblex в действия над моделью.
- Добавляем слой или сервис, когда у него есть конкретная ответственность. Для небольшой задачи достаточно функции рядом с кодом, который её использует.

## Реализация и проверка

- Состояние экземпляра редактора хранится в Angular Signals. Компоненты читают сигналы и вызывают именованные операции, например `moveNodes` и `connect`.
- Идентификаторы блоков и портов стабильны. Связь ссылается на порты по ID. Координаты в модели заданы в системе координат схемы.
- Перед изменением холста сверяем API с `node_modules/@foblex/flow/AI.md`. Для темизации и стилей используем `node_modules/@foblex/flow/STYLING.md`.
- Изменение модели или формата хранения проверяем тестом на соответствующий сценарий. Жесты, геометрию и восстановление вида проверяем в браузере. Для сборки используем `ng build workflow-editor` и `ng build workflow-designer`.
