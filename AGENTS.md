# Process Studio

## Приложение и библиотеки

- В `src/app/app-routing.module.ts` связываем URL с функциональными разделами. Разделы загружаются лениво из `src/app/lazy-modules`. Дочерние маршруты, layout и страницы принадлежат разделу.
- Страница собирает компоненты для своего маршрута. Код с самостоятельной ответственностью можно вынести в библиотеку в `projects/`. Потребители импортируют библиотеку по имени пакета. Её публичные компоненты и типы экспортируются из `src/public-api.ts` внутри библиотеки.
- Договорённости, специфичные для отдельной библиотеки, описываем в её собственном `AGENTS.md`.

## Зависимости и состояние

- В `domain` описываем предметные модели и правила на TypeScript. Этот код должен работать без Angular, браузера и хранилища.
- В `data-access` проверяем и преобразуем данные на границе с API или хранилищем. Предметные правила берём из `domain`, чтобы загрузка и редактирование следовали одним и тем же правилам.
- В `presentation` компоненты отображают состояние и передают действия пользователя коду, который этим состоянием управляет. Состояние на Angular Signals располагаем у ближайшего общего владельца. Потребители получают сигналы для чтения и методы для изменений.
- Добавляем сервис или слой, когда у него появляется своя ответственность.

## Проверка изменений

- Доменное правило проверяем тестом с конкретными входными данными и ожидаемым результатом. Изменения маршрутов проверяем через Angular Router.
- При изменении формата сохранения проверяем чтение данных предыдущей версии. Поведение, зависящее от геометрии страницы или действий указателя, проверяем в браузере.
